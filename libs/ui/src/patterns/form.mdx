# Form

How every form in DevMentor behaves. The example is the mentor page form; the behaviour belongs to every form.

Backlog: E01-S02 (#18), E02-S02 (#21), E02-S04 (#23), E05

## When to use

- Any screen where a person types and saves: sign-in, mentor page, prices, a note.

## Rules

| Rule                                                                                              | Source                |
| ------------------------------------------------------------------------------------------------- | --------------------- |
| A label is always visible; the placeholder is only an example                                     | task rule, WCAG 3.3.2 |
| Only optional fields are marked, with "(Optional)"                                                | Q-C                   |
| An error appears after the person leaves a field and again on submit                              | task rule             |
| After a failed submit focus moves to the first field with an error                                | task rule, WCAG 3.3.1 |
| What the person typed stays after a failure                                                       | task rule             |
| A second submit is ignored while one is running                                                   | task rule             |
| Success is shown only after the server confirms                                                   | task rule             |
| An error says what to do next, not only what is wrong                                             | WCAG 3.3.3            |
| Server errors come back as field errors, a server error, or no network, each with its own message | task rule             |

## Components used

- Field
- Text field, Textarea, Select, Checkbox, Radio group
- Button (`loading`)
- Alert
- `FormSubmitState` and `postJson` helpers

## What to avoid

- A placeholder in place of a label.
- A success message before the server answers.
- Clearing the form after an error.
- A toast for an error that needs action.
