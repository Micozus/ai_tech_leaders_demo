# Sign-in panel

Sign in with GitHub, or with email and password. The email form is the form pattern.

Backlog: E01-S01 (#17), E01-S02 (#18)

<Unstyled>
  <Canvas of={Stories.Playground} story={{ height: '460px' }} />

<Controls of={Stories.Playground} />

## What it is for

One place to start a session for every role (R06): GitHub first, email and password as the fallback.

## When to use

- The sign-in page and any "sign in to continue" screen.

## When not to use

| Situation                 | Use instead                                      |
| ------------------------- | ------------------------------------------------ |
| Creating a mentor account | The invitation panel (R07: no open registration) |
| A signed-in screen        | App header                                       |

## Anatomy

| Part               | Component               | Notes                                            |
| ------------------ | ----------------------- | ------------------------------------------------ |
| Container          | Card (roomy)            | Heading "Sign in"                                |
| GitHub button      | Button (quiet, block)   | `pi-github` icon, "Sign in with GitHub"          |
| Failure notice     | Alert (danger)          | GitHub failure and the generic credentials error |
| Email and password | Field + Text field      | Validation after leaving a field and on submit   |
| Submit             | Button (primary, block) | Shows `loading` while sending                    |

## Data states

| State                           | What the person sees                                       | Story                 |
| ------------------------------- | ---------------------------------------------------------- | --------------------- |
| Idle                            | Both ways offered                                          | Playground            |
| GitHub failed                   | Alert above the buttons: "GitHub sign-in did not complete" | Github Failed         |
| Wrong password or unknown email | One generic message, never which of the two                | Wrong Password        |
| Submitting                      | The button is busy; a second submit is ignored             | Submitting            |
| Server error / offline          | Message with the data kept                                 | Server Error, Offline |

## Behavior and accessibility

| Topic             | Rule                                                                           | Source                        |
| ----------------- | ------------------------------------------------------------------------------ | ----------------------------- |
| Focus             | After a failed submit focus moves to the first field with an error             | Form pattern                  |
| Errors            | Field errors are announced (`role="alert"`) and linked with `aria-describedby` | WCAG 3.3.1                    |
| Account existence | A wrong password and an unknown email give the same message                    | E01-S02 acceptance, standards |
| Autofill          | `autocomplete="email"` and `current-password`                                  | WCAG 1.3.5                    |
| Keyboard          | Every control is reachable; Enter submits the form                             | WAI-ARIA                      |

## API

| Input or output | Type                                | Default  | Description                                                    |
| --------------- | ----------------------------------- | -------- | -------------------------------------------------------------- |
| submitter       | `(value) => Promise<SubmitOutcome>` | required | Sends the credentials; the panel never uses the network itself |
| githubFailed    | `boolean`                           | `false`  | Shows the GitHub failure notice                                |
| githubSignIn    | `output`                            |          | The person chose GitHub                                        |
| signedIn        | `output`                            |          | The server confirmed the sign-in                               |

## Code

```html
<ui-sign-in-panel
  [submitter]="signIn"
  [githubFailed]="failed()"
  (githubSignIn)="startGithub()"
  (signedIn)="goHome()"
/>
```
