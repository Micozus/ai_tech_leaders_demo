# Card

A panel with a heading: a 1px line, no shadow. It groups related content on a page.

<Unstyled>
  <Canvas of={Stories.Playground} story={{ height: '260px' }} />
</Unstyled>
<Controls of={Stories.Playground} />

## What it is for

A card groups content that belongs together under one heading, so a screen reads as a few clear parts.

## When to use

- A group of related fields or data on a detail view (mentor page, booking summary). Source: R01.1.
- A form section with its own heading. Source: P10 (roomy).
- A dense block of data in a list or a dashboard (dense).

## When not to use

| Situation                     | Use instead                                                |
| ----------------------------- | ---------------------------------------------------------- |
| A list of rows                | Rows separated by a 1px line, not one card per row (R01.1) |
| A panel inside a panel        | Split the screen, or use a line inside the panel (A01)     |
| A message                     | Alert                                                      |
| Grouping radios or checkboxes | `fieldset` with `legend`                                   |

## Anatomy

| Part    | Required | Notes                                                                |
| ------- | -------- | -------------------------------------------------------------------- |
| Heading | yes      | `role="heading"` with a level (2 to 4) that follows the page outline |
| Body    | yes      | Projected content                                                    |
| Border  | yes      | 1px `line`; there is no shadow                                       |

## Variants

Density follows the screen type (P10).

| Variant | Choose it when                                 | Source |
| ------- | ---------------------------------------------- | ------ |
| dense   | Lists and data: 16px padding                   | P10    |
| roomy   | Sessions, forms and detail views: 24px padding | P10    |

Hover, focus and pressed are frozen previews built from the component's own hover and focus declarations (documentation only).

| State                   | What changes                                                              | Source   |
| ----------------------- | ------------------------------------------------------------------------- | -------- |
| Default                 | `surface` fill, 1px `line`, 8px radius                                    | D3, D17  |
| Hover / Focus / Pressed | A card is not interactive; make the heading a link or put a button inside | n/a      |
| Disabled                | Not applicable                                                            | n/a      |
| Loading                 | Replace the body with skeletons and set `aria-busy`                       | proposal |
| Selected                | Not applicable                                                            | n/a      |
| Error                   | Put an error state or an alert inside the body                            | n/a      |

**Disabled:** a card is never disabled. If its content is unavailable, say why in the body.

## Behavior and accessibility

| Topic         | Rule                                                                         | Source               |
| ------------- | ---------------------------------------------------------------------------- | -------------------- |
| Keyboard      | Not focusable; the controls inside are                                       | WAI-ARIA             |
| Focus order   | Reading order of the body                                                    | WCAG 2.4.3           |
| Role and name | A `section` with a heading; the level is an input so the outline never skips | WCAG 1.3.1           |
| Screen reader | Announces the heading and its level                                          | native               |
| Colour        | The border is decorative                                                     | WCAG 1.4.11 (exempt) |
| Target size   | Controls inside keep their own sizes                                         | WCAG 2.5.8           |

## Content

| Topic            | Rule                                         | Source    |
| ---------------- | -------------------------------------------- | --------- |
| Heading          | A noun phrase: "Upcoming sessions", "Prices" | task rule |
| Length           | Up to about 50 characters; longer wraps      | proposal  |
| Numbers          | Format with units: "€45.00", "50 minutes"    | R14       |
| Longer languages | The panel grows; nothing truncates           | proposal  |

## API

| Input        | Type             | Default  | Description                       |
| ------------ | ---------------- | -------- | --------------------------------- |
| heading      | `string`         | required | The panel title                   |
| density      | `dense \| roomy` | `dense`  | Padding by screen type            |
| headingLevel | `2 \| 3 \| 4`    | `2`      | Heading level in the page outline |

Selector: `ui-card`. Body content is projected.

## Code

Minimal:

```html
<ui-card heading="Upcoming sessions">…</ui-card>
```

In DevMentor:

```html
<ui-card heading="Prices" density="roomy" [headingLevel]="2">
  <ui-field label="25 minutes" controlId="p25"
    ><input ui-text-field id="p25"
  /></ui-field>
  <ui-field label="50 minutes" controlId="p50"
    ><input ui-text-field id="p50"
  /></ui-field>
  <button ui-button>Save prices</button>
</ui-card>
```

## Do and don't

<Unstyled>
  <Canvas of={Stories.DoAndDont} story={{ height: '460px' }} />
</Unstyled>

- One panel groups related content under one heading. Source: R01.1.
- No panel inside a panel. Source: A01.
- Heading levels follow the page. Source: WCAG 1.3.1.
