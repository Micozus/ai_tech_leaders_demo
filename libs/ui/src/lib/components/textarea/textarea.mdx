# Textarea

A native multi-line `<textarea>` with the DevMentor look. Use it inside `ui-field` so it always has a visible label.

## What it is for

A textarea lets a person write more than a line: a mentor description, a comment when declining a note.

## When to use

- The mentor description on the mentor page (E02-S02).
- The comment when a mentee declines a note (E04-S04).
- The written answer and the note draft (E04-S02, E04-S03).

## When not to use

| Situation                      | Use instead                      |
| ------------------------------ | -------------------------------- |
| A single short value           | Text field                       |
| A choice among known values    | Radio group, Select or Checkbox  |
| Formatted content (not in 1.0) | Not built; see "What is missing" |

## Anatomy

| Part    | Required            | Notes                                                    |
| ------- | ------------------- | -------------------------------------------------------- |
| Label   | yes (in `ui-field`) | Always visible                                           |
| Control | yes                 | Native `<textarea>`, at least 40px, resizable vertically |
| Hint    | no                  | What to write or the limit                               |
| Error   | when invalid        | Text with the reason, announced                          |

## Behavior and accessibility

| Topic         | Rule                                                                          | Source            |
| ------------- | ----------------------------------------------------------------------------- | ----------------- |
| Keyboard      | Tab focuses; Enter adds a new line; Tab leaves the field                      | WAI-ARIA APG      |
| Focus order   | Visual order                                                                  | WCAG 2.4.3        |
| Role and name | Native textarea named by its label; hint and error through `aria-describedby` | WCAG 1.3.1, 3.3.2 |
| Invalid       | `aria-invalid="true"` plus an error with `role="alert"`                       | WCAG 3.3.1        |
| Resize        | The user can resize vertically; text stays reachable at 200% zoom             | WCAG 1.4.4        |
| Target size   | At least 40px high                                                            | WCAG 2.5.8        |

## API

| Input   | Type      | Default | Description                      |
| ------- | --------- | ------- | -------------------------------- |
| invalid | `boolean` | `false` | Danger border and `aria-invalid` |

Selector: `textarea[ui-textarea]`. `rows`, `maxlength`, `value`, `disabled` and forms bindings stay native.

## Code

Minimal:

```html
<textarea ui-textarea id="about" rows="4"></textarea>
```

In DevMentor:

```html
<ui-field
  label="Comment for the mentor"
  controlId="comment"
  hint="Say what to change. The mentor will rewrite the note."
>
  <textarea
    ui-textarea
    id="comment"
    rows="4"
    aria-describedby="comment-hint"
  ></textarea>
</ui-field>
```

## Do and don't

<Unstyled>
  <Canvas of={Stories.DoAndDont} story={{ height: '360px' }} />
</Unstyled>

- A visible label and a hint that says what to write. Source: WCAG 3.3.2.
- Do not use a textarea for one short value. Source: proposal.
- Keep what the person wrote when the submit fails. Source: task rule (form pattern).
