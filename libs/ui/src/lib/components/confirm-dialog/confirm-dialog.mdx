# Confirm dialog

A dialog that asks before something that cannot be undone. It names the object, offers the way out first and says what the confirming button does.

## What it is for

A confirm dialog prevents a costly slip: cancelling a booking, declining a note, removing a slot.

## When to use

- Cancel a booking, especially inside 24 hours when the fee is forfeited (E03-S05, R09).
- Decline a note, which sends it back to the mentor (E04-S04).
- Any action that cannot be undone or costs money.

## When not to use

| Situation                    | Use instead                                    |
| ---------------------------- | ---------------------------------------------- |
| An action that can be undone | Act, then confirm with a toast, and offer undo |
| A harmless confirmation      | Nothing                                        |
| A choice between two options | Radio group or two buttons                     |
| Anything that needs a form   | Dialog or a page                               |

## Anatomy

| Part              | Required | Notes                                                 |
| ----------------- | -------- | ----------------------------------------------------- |
| Heading           | yes      | The question: "Cancel this booking?"                  |
| Object            | yes      | The name of what is affected, in bold                 |
| Consequence       | no       | What will happen, in `muted` text                     |
| Way out           | yes      | The first button; takes focus; "Keep booking"         |
| Confirming button | yes      | A verb phrase in the danger variant: "Cancel booking" |

## Variants

The confirming button is `danger` by default.

| Variant | Choose it when                                                     | Source   |
| ------- | ------------------------------------------------------------------ | -------- |
| danger  | Destructive or costly (default)                                    | R09, D12 |
| primary | A consequential but not destructive decision: set `confirmVariant` | proposal |

## API

| Input                 | Type                | Default   | Description                          |
| --------------------- | ------------------- | --------- | ------------------------------------ |
| heading               | `string`            | required  | The question                         |
| objectName            | `string`            | required  | Name of the affected object          |
| confirmLabel          | `string`            | required  | Verb phrase on the confirming button |
| description           | `string`            | `""`      | The consequence                      |
| cancelLabel           | `string`            | `Keep it` | Text of the way-out button           |
| confirmVariant        | `ButtonVariant`     | `danger`  | Variant of the confirming button     |
| open                  | `boolean` (two-way) | `false`   | Shows or hides                       |
| confirmed / cancelled | `output`            |           | Emitted before the dialog closes     |

Selector: `ui-confirm-dialog`.

## Code

Minimal:

```html
<ui-confirm-dialog
  heading="Cancel this booking?"
  objectName="Architecture review, Thursday 14:00"
  confirmLabel="Cancel booking"
  [(open)]="open"
  (confirmed)="cancel()"
/>
```

In DevMentor:

```html
<ui-confirm-dialog
  heading="Cancel this booking?"
  objectName="Architecture review with Ada Lovelace, Thursday 14:00"
  description="You are inside the 24 hours before the session, so the fee is not refunded."
  confirmLabel="Cancel booking"
  cancelLabel="Keep booking"
  [(open)]="open"
  (confirmed)="cancelBooking()"
/>
```

## Do and don't

<Unstyled>
  <Canvas of={Stories.DoAndDont} story={{ height: '460px' }} />
</Unstyled>

- The question names the object. Source: task rule.
- The way out is easy to find and takes focus. Source: task rule, WCAG 3.3.4.
- The confirming button is a verb phrase, never "OK". Source: task rule.
