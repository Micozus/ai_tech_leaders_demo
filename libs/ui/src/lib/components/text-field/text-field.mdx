# Text field

A native single-line `<input>` with the DevMentor look. Use it inside `ui-field` so it always has a visible label.

## What it is for

A text field lets a person type one short value: a link, a name, an email, a price.

## When to use

- A public-work link or a display name (E02-S02).
- Email and password on the sign-in form (E01-S02).
- A short answer of one line.

## When not to use

| Situation                                          | Use instead                                           |
| -------------------------------------------------- | ----------------------------------------------------- |
| Several lines of text (the written answer, a note) | Textarea                                              |
| One of a few known values                          | Radio group or Select                                 |
| A yes or no                                        | Checkbox                                              |
| Dates and times                                    | A date and slot picker (product component, not built) |

## Anatomy

| Part    | Required            | Notes                                              |
| ------- | ------------------- | -------------------------------------------------- |
| Label   | yes (in `ui-field`) | Always visible; the placeholder is only an example |
| Control | yes                 | Native `<input>`, 40px high                        |
| Hint    | no                  | Format or limit, in `muted` text below             |
| Error   | when invalid        | Text with the reason and how to fix it, announced  |

## Variants

There is one look. The input `type` is native (`text`, `email`, `url`, `password`).

| Variant | Choose it when                                         | Source |
| ------- | ------------------------------------------------------ | ------ |
| default | All short text                                         | D1     |
| invalid | After a failed check: danger border and `aria-invalid` | D22    |

## Behavior and accessibility

| Topic         | Rule                                                                                         | Source                   |
| ------------- | -------------------------------------------------------------------------------------------- | ------------------------ |
| Keyboard      | Tab focuses; typing edits; Esc does nothing special                                          | WAI-ARIA APG             |
| Focus order   | Visual order; after a failed submit focus moves to the first invalid field                   | task rule (form pattern) |
| Role and name | Native input named by its `<label for>`; `aria-describedby` points to the hint and the error | WCAG 1.3.1, 3.3.2        |
| Invalid       | `aria-invalid="true"` plus an error with `role="alert"`                                      | WCAG 3.3.1               |
| Autofill      | Use the right `type` and `autocomplete`                                                      | WCAG 1.3.5               |
| Target size   | 40px high                                                                                    | WCAG 2.5.8               |

## Content

| Topic       | Rule                                                                                                         | Source    |
| ----------- | ------------------------------------------------------------------------------------------------------------ | --------- |
| Label       | A noun phrase: "Public-work link". Optional fields get "Optional" in `muted`; required fields are not marked | Q-C       |
| Placeholder | An example value, never the name                                                                             | task rule |

## API

| Input   | Type      | Default | Description                      |
| ------- | --------- | ------- | -------------------------------- |
| invalid | `boolean` | `false` | Danger border and `aria-invalid` |

Selector: `input[ui-text-field]`. `type`, `value`, `placeholder`, `disabled`, `autocomplete` and forms bindings stay native.

## Code

Minimal:

```html
<input ui-text-field id="work" type="url" />
```

In DevMentor:

```html
<ui-field
  label="Public-work link"
  controlId="work"
  error="Enter a link that starts with https://"
>
  <input
    ui-text-field
    id="work"
    type="url"
    [invalid]="true"
    aria-describedby="work-error"
  />
</ui-field>
```

## Do and don't

<Unstyled>
  <Canvas of={Stories.DoAndDont} story={{ height: '320px' }} />
</Unstyled>

- A visible label on every field. Source: task rule, WCAG 3.3.2.
- The placeholder is an example, not the name. Source: task rule.
- The error says what to do, not only what is wrong. Source: WCAG 3.3.3.
